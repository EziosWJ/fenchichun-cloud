# 临时往来主体与总部归并

本文记录已确认的首期需求。云端负责接收登记、总部确认和磅单归集，厂端负责现场登记和应用归并结果。双方共同的目标与现行同步行为见[厂云同步契约](cloud-sync-contract.md#临时往来主体首期目标)。

## 厂端登记

- 云端资料模式下，有权限的厂端操作员可新增临时往来主体，填写名称、主体性质和业务身份。厂端生成稳定且与总部主体编码区分的临时编码，保存后立即可用于本厂普通过磅，断网时也可办理。需要绑定粮食流转单的业务沿用流转单上的正式供货方。物料沿用现行资料管理规则。
- 厂端保存登记和待上传记录后，由厂端主动通过独立 HTTP 接口上送。上送在保存时触发，断网恢复后继续。磅单按现有流程独立上传，可先于主体登记到达云端。
- 云端用厂区和临时主体编码定位登记。首次接收后进入待确认列表，重复上送同一版本只产生一条记录。云端登记表保存名称、主体性质、业务身份、版本、处理状态及归并结果。列表直接查询登记记录。
- 归并前，厂端可沿用原编码更正同一主体的资料并上送新版。云端保留较新的版本。总部确认时校验所核对的版本，发现资料已更新时提示重新核对。

## 总部确认

- 具备总部往来主体维护权限的人员可关联已有正式主体，也可按现有规则新建正式主体后关联。提交前展示发起厂、临时主体、拟关联的正式主体和业务身份。确认保存正式主体编码、确认人和确认时间。
- 归并目标须已启用，并覆盖临时主体的业务身份。总部人工核实实际业务归属，例如个人送货的登记可归并至负责结算开票的企业。正式主体缺少所需业务身份时，可按正式资料规则补齐。同名只提示核对。正式主体按现有规则向所有厂区共享，归并结果仅返回给发起厂。
- 统一社会信用代码和身份证号码均为选填。总部有足够依据确认身份时，可以在证件留空的情况下建档并归并；证件填写和编辑规则见[供应商资料规则](laboratory-phase-one.md)。临时登记只上送名称、主体性质和业务身份。
- 身份仍无法确认时，总部可标记待补资料并说明原因，现场可继续使用该临时主体办理普通过磅。确认登记错误时，走明确的停用操作。首期归并确认后关系固定，撤销和改绑延后。
- 厂端登记及拉取沿用现有厂云 HTTP 接入方式，云端按请求中的有效厂区编码处理。总部确认操作由云端校验操作员权限。

## 归并下发与厂端切换

- 厂端主动拉取全量基础资料时，同时取得本厂的归并结果。只有在一次本地事务里确认正式主体已入库、已启用且可用于所需业务身份，才把临时主体标记为已归并并移出新开单候选。正式主体暂不可用时，保留临时主体的现场可选状态，待后续同步满足条件再切换。
- 全量资料仍按总部主体映射更新。临时主体及其编码保留在本地。同名正式主体随快照下发时，临时主体继续可选，直到收到可生效的明确归并结果。
- 已生效归并的正式主体后来停用时，临时主体保持已归并。已首磅任务可按原主体快照完成回磅，历史磅单保留原编码和名称。

## 云端磅单归集

- 正式主体的汇总、按主体筛选的对账明细及重新导出，按当前有效归并关系纳入同厂临时编码下的磅单。磅单明细保留开单时的编码和名称，已导出的文件保留当时结果。
- 磅单先于登记到达时，按原快照入库并可查；归并关系建立后，重新查询即可按正式主体归集。

## 验收场景

1. 厂端断网新增临时主体，当场可以首磅；恢复联网且尚未回磅时，总部已能看到登记。重复上送后仍只有一条待确认记录。
2. 云端先收到磅单，后收到登记。磅单在登记到达前可以查询，并在确认归并后纳入正式主体对账。
3. 厂端更正登记后，总部使用旧版本确认时收到重新核对提示。正式目标缺少所需业务身份时，补齐后才可确认。
4. 全量下发带有同名正式主体时，临时主体仍可选。收到本厂归并结果且正式目标可用后，新任务改选正式主体，待回磅任务能按原快照出单。
5. 生效归并的正式主体停用后，临时主体保持已归并。其他厂可收到正式主体资料，查询各自归并结果时只得到本厂记录。
6. 总部确认个人送货的三张临时主体磅单归属负责开票的正式企业。与企业原有两张磅单落在同一对账条件内时，按企业查询或重新导出可见五张，逐单明细仍展示原快照。

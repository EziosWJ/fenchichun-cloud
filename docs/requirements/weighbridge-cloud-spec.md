# 云端过磅业务：第一版规格

本文仅记录综合管理大平台中云端过磅业务的已确认目标；云端过磅业务正在开发，厂云端到端同步尚未完成。厂云共同业务边界见[厂云同步契约](cloud-sync-contract.md)，两端同步维护；本次过磅同步涉及的单据字段、业务细则及例外以本地过磅系统有效规格为准。本文不定义平台其他业务的范围或规则。

多项净重调整（schemaVersion 5 / digestVersion 3）的比例基数已确认为最终毛重减最终皮重，完整协议见[厂云同步契约](cloud-sync-contract.md)。云端已实现接收、保存、展示与按合计统计；含多项调整的单据在类别/方式报表中归为“多项调整”，不拆分统计。尚未部署、未连接真实业务库，未完成与厂端的真实联调。

## 范围

本次各厂正式投入使用时即接入云端，目前各厂尚未使用，本次无需历史资料或单据导入。总部统一维护物料、分类、往来主体和联系人，向所有厂提供完整资料；总部资料维护权限现阶段不讨论。云端以厂区编码核对并归属同步数据，不登记地磅或使用厂端凭据；厂端地磅编码用于本地业务。总部人员可查询所有厂区，不按厂区限制查询范围。

云端接收本厂已出过磅单及约定的重量和联系信息，支持查询和按有效单最终净重统计；作废更新原单，重开形成关联新单。照片和打印记录保留本厂，单据办理由厂端负责。总部接受同步滞后及原单作废与新单重开之间暂时少计，查询页面提示数据可能尚未同步。

## 总部待回磅列表（首期设计）

- 列表供获授权的总部用户跨厂只读查询。默认显示待回磅，可按厂区、车牌及任务状态查询。待回磅行展示厂区、任务号、车牌、方向、物料、供收方、首磅时间和等待时长。
- 已终止任务保留在同一列表，可筛选查询，并展示终止时间、人员和原因。云端已收到出单状态但正式磅单还未入库时，显示「已出单，待上传」，该行不计入待回磅数量。收到两项数据后，任务移出列表，用户到正式磅单查询。
- 展示每厂最近成功同步时间。连续五分钟没有成功同步时提示数据可能滞后，并保留最后收到的内容。同步正常且无待回磅任务的厂区显示为零，从未同步的厂区显示「尚未同步」。
- 首次上线纳入当时仍待回磅的任务。上线前已终止的历史由厂端留存。正常联网时，厂端变化在一分钟内可见是交付目标。

## 人工补单在云端的查询和对账（首期设计）

- 在正式磅单查询中支持「人工补单」筛选，详情展示人工补单标记、两次实际称重时间、人工重量来源和实际出单时间。人工补录回磅沿用既有显示。补单原因和现场依据由厂端留存。
- 对账沿用原日期筛选。人工补单以实际回磅日归属，北京时间回磅日期用于对账列表、明细和导出；普通磅单沿用现有口径。举例：17 日回磅、18 日补单，在 17 日的对账中出现，详情显示 18 日出单。
- 人工补单按正式磅单参与有效净重统计，作废单排除，重开后只计有效新单。

两项首期业务范围见[厂云同步契约](cloud-sync-contract.md)，拟定字段、回执和兼容规则见[新增同步接口契约](weighbridge-task-and-manual-ticket-api.md)。

## 验收目标

- 首次绑定和完整资料同步成功后正式使用；每小时及主动同步完整资料，失败不产生部分更新，本厂使用上一版继续正常业务。
- 云端校验请求中的厂区编码存在且启用，并按编码归属；编码不构成厂端来源认证。按约定接收单据变化并确认，重复变化不重复出单，同单据变化及关联重开按约定顺序处理。
- 断网出单、作废和重开后可补传；云端按收到的当前有效单及最终净重统计，作废排除，重开不重复统计。
- 关闭同步后的本地资料处理按[厂云同步契约](cloud-sync-contract.md)执行；不开发自动匹配或合并。恢复旧备份后流水号倒退的处理继续暂缓。

基础资料接口见[接口设计](weighbridge-sync-api-design.md)，单据接口细节仍待双方联调；开发依赖和验证顺序见[云端开发准备](weighbridge-cloud-development.md)。

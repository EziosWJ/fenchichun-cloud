# 小程序架构初始化：实施方案与验收

状态：已获准实施；TASK-01～06 均为 P0，实际验收结果另见 miniprogram/docs/acceptance/。

实施调整：用户明确要求小程序改用 npm，使用 package-lock.json 和 npm ci；本文原 pnpm 规划由该约定取代，web 继续使用 pnpm。
日期：2026-11-06。

## 1. 目标与范围

建立可重复安装、构建、运行和验证的微信小程序基础工程。首阶段只提供登录、工作台、个人中心骨架及 Mock 数据，不接入业务，不预设服务端登录接口，不确定最终底部导航。

小程序在现有 `miniprogram/` 内开发。`web/` 保持 React + Ant Design 既有约定；本方案中的 TDesign、Tailwind 和 wx.request 只适用于小程序。现有 Go 接口不能直接视为小程序登录契约。

本次交付仅为实施方案和验收文档，不安装依赖、不调整 MCP、不修改运行代码。

## 2. 已核对的仓库现状

- 已有 `miniprogram/`，package 名为 `weapp-vite-template`，使用 weapp-vite，不能按空目录重新初始化。
- `AGENTS.md` 为生成文件，来源标记为 `template:default`，要求保留生成规则，将项目补充规则放入 `AGENTS.local.md`。
- 已有 TypeScript、ESLint、Stylelint、SCSS 和开发/构建脚本；package.json 尚无 packageManager、typecheck、test 脚本，目录中未见 pnpm-lock.yaml。
- 构建配置实际为 `weapp-vite.config.ts`，srcRoot 为 `src`；生成规则提及 vite.config.ts，实施时须核对当前工具实际加载路径，不能据文件名描述盲目改名。
- 微信项目配置指向 `dist/`，appid 为 `touristappid`，基础库为 `3.13.2`。这些是现状，兼容性和自动化权限尚未验证。
- Node engines 已有限制，但需要验证目标 Node 版本是否可获取、依赖组合是否可安装，不直接沿用未经验证的范围。
- 根 Taskfile 尚无小程序任务入口。

以上为静态检查结果；未声称现有项目能够构建、截图或读取运行日志。

## 3. 实施决策与顺序

默认方向：保留 weapp-vite 工具链，以同版本脚手架的 `tdesign` 模板为对齐基线，继续原生小程序 + TypeScript。先在临时目录比对模板，记录生成器版本、模板来源和差异，再最小化合入现有 miniprogram；不覆盖现有 AGENTS.md，不直接改用其他 TDesign 行业模板。

执行顺序：TASK-01 → TASK-02；TASK-01 → TASK-03、TASK-04；TASK-03 + TASK-04 → TASK-05；TASK-06 的静态检查与 CI 随 TASK-01 建立，最终在 TASK-02～05 完成后跑完整闭环。

实施前核对事项：

1. 锁定 weapp-vite 对应版本文档中的 tdesign 模板参数、Node/pnpm 兼容范围、MCP 启动入口及 Tailwind 集成方式，不使用未锁版本的 latest 命令作为日常安装入口。
2. 确认可用 AppID、开发者权限、开发者工具登录态、服务端口、CLI 路径。缺少权限时仍可完成静态验收，但运行和截图不得标记通过。
3. 确认 Windows 微信开发者工具可以访问当前 WSL UNC 项目路径；若不支持，验证受控 Windows 镜像目录方案，明确唯一源码目录和同步方式，禁止两侧独立修改。
4. API BaseURL 使用显式配置；尚无地址时使用占位并给出清晰校验，不将开发机 localhost 作为真机地址。

## 4. TASK-01：项目初始化与工程规范

### 工作与交付

- 比对并对齐 tdesign 模板，保留来源、许可和必要依赖，移除本次引入但与基础骨架无关的演示页面。
- 固定经过安装和构建验证的 Node、pnpm 精确版本：版本文件、engines、packageManager、CI 保持一致。提交 pnpm-lock.yaml，安装使用冻结锁文件，不引入第二套锁文件。
- 保留 TypeScript 严格检查；统一配置源码别名，例如 `@/`。同时覆盖 TypeScript 解析和构建产物解析，检查 WXML/JSON 组件路径，不能只以编辑器无报错验收。
- 接续 ESLint 和 Stylelint；核对小程序 runtime 规则生效范围。格式化优先复用现有配置的修复能力，确有缺口再选择单一格式化工具。
- 完善 README、.gitignore，忽略依赖、产物、日志、本地环境配置、开发者工具私有配置，保留锁文件和必要的 .env 示例。
- 定义 development、test、production 构建模式。环境配置由构建时显式注入，应用代码不依赖 Node 的 process.env。
- 约定配置键为运行环境、API BaseURL、Mock 开关；应用内不存在可保密的密钥。生产构建强制禁用 Mock，禁止误回退开发地址。
- 检查 project.config.json 的源码/产物根目录、编译类型、基础库、renderer 和 npm 产物路径；真实 AppID 和私有设置的填写方式写入 README，不提交个人机器路径。
- 新增 Taskfile 的 miniprogram:install、lint、format:check、typecheck、test、build、check 入口；各任务调用小程序 package scripts，不改变现有 Web/Go 默认入口。

### 验收

在隔离的全新检出目录，按 README 配置版本与非敏感环境参数，运行冻结安装、lint、format:check、typecheck、test 及三个环境的构建，退出码均为 0。安装不能修改锁文件；dist 含可导入的 app.json、页面及 TDesign 组件依赖。记录工具版本、命令、耗时和结果。

类型错误样例必须让 typecheck 失败，未解析别名必须使构建失败；验收后移除探针。生产产物检查 Mock 关闭，测试环境不会落到生产地址。微信开发者工具实际导入并编译成功，不能只验证 Vite 返回 0。

## 6. TASK-03：UI 基础规范与公共组件

### 工作与交付

- 建立颜色、字体、间距、圆角规范，颜色优先映射 TDesign 语义 Token；间距采用少量固定档位，普通正文建议 28rpx，正文行高约 1.5。
- 统一页面背景、内容留白、顶部导航、安全区及长页面滚动策略。首版采用系统导航栏并封装一致配置；PageHeader 是页面内容标题，避免重复占用状态栏。需要自定义导航时另行明确胶囊避让和返回行为。
- TDesign 承担交互组件，Tailwind 只承担布局和间距；使用当前构建链支持的小程序适配方案。关闭或限定全局 reset，避免覆盖 TDesign 内部样式，不使用无法静态提取的动态类名拼接。
- 小范围公共组件放入现有 src/components；页面容器放入 src/layouts。建立组件演示页验证两套样式协作，不提前建设通用组件平台。

### 验收

保存实际微信开发者工具截图；另在至少一台真机验证安全区、字体与交互并记录型号、系统、微信版本和截图。模拟器截图不能单独证明真机通过。

## 7. TASK-04：API 请求层与认证基础

### 工作与交付

- 在 src/utils/api 中封装 Promise 风格 wx.request，页面不直接发起底层请求。支持方法、数据、请求头、统一超时和显式免认证选项。
- 统一响应类型暂按本仓库 `{ code, message, data }`、成功 code=200 约定；分页等业务契约本任务不扩展。登录路径、凭据格式、Token 字段和刷新协议全部留待正式契约确认。
- 明确处理次序：传输失败 → HTTP 状态 → 响应结构 → 业务码 → data；HTTP 非 2xx 不作为成功返回，HTTP 200 的业务失败也必须拒绝。
- 标准化错误分类：HTTP、业务、超时、网络、响应格式；保留可展示 message 和必要诊断字段。底层不重复弹窗，由页面或统一反馈入口展示。
- 本地会话模块只提供保存/读取/清除 Token、恢复状态及状态变更通知；不引入复杂状态库，不把本地已登录视为服务端有效认证。
- 有 Token 时注入 Authorization: Bearer；免认证请求不注入。HTTP 401 统一清除会话并通知入口；业务登录过期码未确认前不猜测。
- 多请求并发 401 只触发一次登录过期反馈与导航；已经处于登录页不循环跳转。禁止自动刷新或重放请求。旧会话请求晚到的 401 不得清除新会话。
- Mock 通过请求适配器或测试替身注入；页面不散布 Mock 判断。生产构建不能启用 Mock，也不能真的向未确认登录接口发请求。

### 验收用例

| 场景 | 预期 |
| --- | --- |
| HTTP 200 + code 200 | 返回类型化 data |
| HTTP 200 + 业务失败 | 返回业务错误和 message |
| HTTP 400/403/404/500 | 返回 HTTP 错误，不误清会话 |
| HTTP 401 | 清会话并通知一次 |
| 并发多个 401、已在登录页 | 无重复反馈与导航循环 |
| 旧请求 401 在新会话建立后返回 | 保留新会话 |
| 超时、断网、请求失败 | 错误分类准确，加载状态结束 |
| 响应不是 JSON 或结构缺字段 | 返回格式错误，不返回伪成功 |
| 有 Token、无 Token、免认证 | 注入规则准确 |
| 重启恢复、退出清除 | 本地状态一致，无真实登录接口依赖 |
| 三种环境、生产 Mock 开关 | 配置隔离，错误配置明确失败 |

使用可控的 wx.request 替身覆盖单元测试，并在 IDE 中以 Mock 适配器验证页面反馈。Mock 验收不代替未来真实域名、HTTPS、证书及微信 request 合法域名联调。

## 8. TASK-05：应用入口与页面骨架

### 工作与交付

- App 生命周期负责初始化环境、恢复本地会话、注册/解绑全局错误反馈；onShow 不反复初始化，生命周期日志只在开发模式输出必要信息。
- 建立登录、工作台、个人中心页面；采用原生 app.json 页面注册和统一路径常量，不引入第二套路由。工作台作为首版可预览入口，Mock 未登录时明确引导登录骨架。
- 页面之间使用普通导航入口，不声明最终 tabBar。返回行为和直接打开目标页面均可验证。
- 登录页面仅展示待接入状态或明确标记的 Mock 登录，不宣称已完成微信登录、手机号登录或已有后端认证。
- 工作台、个人中心只展示占位 Mock 数据，不推导业务模块。覆盖加载、空、失败、成功、重试状态。
- 局部请求使用 LoadingState；确需全局加载时正确配对开始/结束，含异常路径。统一反馈避免同一个错误弹出多次，不向用户展示堆栈。

### 验收

冷启动、进入后台再返回、页面跳转/返回、直接打开三个页面、Mock 登录/退出均可操作。模拟接口失败后能重试，网络失败不造成永久遮罩。三页分别保存正常态截图，工作台额外保存加载、空和错误态；控制台无未处理异常或资源缺失。

## 9. TASK-06：自动化测试与交付

### 工作与交付

- 基础检查包含 lint、格式、类型、API/认证关键用例及生产构建；使用最少必要测试工具，不为每个展示组件编写镜像测试。
- GitHub Actions 在小程序、工作流或相关 Taskfile 变更时运行冻结安装和静态检查，固定 Node/pnpm；失败必须阻断工作流。产物与失败日志按保留期上传，缓存键包含版本和锁文件。
- 通用 CI runner 承担静态检查与构建；需要登录态和 GUI 的 IDE 自动化在本地或专用自托管 runner 执行，不默认 GitHub 托管 Linux 能启动微信开发者工具。
- 接入开发者工具自动化，复用 weapp-vite 支持的能力。提供带超时、串行执行、明确错误输出和清理的 miniprogram:accept 入口；若依赖前台 IDE，明确记录前置条件。
- CLI 截图优先使用 `pnpm exec wv screenshot`，基准比较优先 `pnpm exec wv compare`。还必须独立验证一次 MCP 发起的截图调用，CLI 成功不等于 MCP 截图通过。
- 首页基准截图使用固定 Mock 数据、视口、renderer、基础库和工具版本，关闭可变时间和随机内容；截图更新必须说明 UI 变化原因。

### 最终端到端验收

1. 从干净检出按 README 安装，执行全部静态检查和构建。
2. 启动开发者工具并核对打开项目、当前代码版本和页面；连接 MCP 和日志桥接。
3. 对工作台实施一次可识别的小修改，执行检查和构建，重新加载当前产物。
4. Agent 操作进入工作台，截图必须体现本次修改，读取本次操作时间范围的运行日志。
5. 检查无未处理异常、组件加载失败或 WXSS/WXML 错误，保存工作台基准截图及比较结果。
6. 结束本次启动进程；保留可复现命令和证据，最终小修改是否保留在提交中需明确说明，不遗留探针。

验收通过要求 Agent 独立完成上述操作；人工仅处理微信登录/授权等必要前置条件。若截图、日志或真机证据缺失，标记对应项待验收，不以静态构建代替。

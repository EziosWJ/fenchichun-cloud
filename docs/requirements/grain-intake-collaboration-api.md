# 原粮入厂一期：厂云协同接口草案

状态：开发规格草案，2026-11-06；2026-11-11 已实现厂端流转单查询、扣减规则和磅单关联接口，其余人员端新建路径仍待评审。已确认采用“本地称重 → 联网同步磅单 → 关联对应流转单”；未实现部分仍为草案。业务依据见[主规格](grain-intake-spec.md)，操作前提见[状态流转](grain-intake-state-machine.md)。

## 1. 权威边界与离线方式

| 数据 | 权威端 | 另一端的职责 |
| --- | --- | --- |
| 流转单、供应商核实、有效化验及扣减规则依据 | 云端 | 厂端沿用明确的业务依据，不自动覆盖 |
| 实际粮仓及卸粮确认 | 云端记录现场事实 | 磅房按现场已确认情况办理，不强制等待在线回执 |
| 现场重量、正式磅单、打印 | 厂端 | 云端联网后接收、核对及关联，不直接修改厂端单据 |
| 出门证审批、实际出厂 | 云端 | 在有效磅单关联后办理正常开证 |

磅房无法连接云端时，本地仍可称重、保存并打印磅单。恢复联网后，先按既有协议同步正式磅单，确认云端已保存，再关联对应流转单。云端未关联有效单前不能正常开证，不能把本地出单成功等同于云端流程完成。

取消此前草案的云端首磅/回磅准备接口，不以云端在线锁定或回执作为本地称重的必要条件。本次不新增首磅实时上传要求；云端不保证实时掌握待回磅任务。

这不取消首磅前确认有效化验、回磅前确认实际粮仓及卸粮的业务规则。磅房离线时如何取得化验及扣减依据、如何传达现场首磅和卸粮事实仍需细化；不推定全部信息已经缓存，也不默认允许跳过化验或随意填写扣减。

库管和门卫手机无法连接云端是另一问题，本次确认不自动扩展为小程序可离线审批或离线放行。

## 2. 复用现有磅单协议

继续使用现有 v4 或双方正式选定的协议同步正式磅单，遵循[厂云同步契约](cloud-sync-contract.md)。不修改现有 `TicketSnapshot`、摘要字段或摘要规则版本，不上传未完成任务冒充正式磅单。

现有磅单协议不包含本趟编号。建议以单独关联命令绑定 `tripNo` 和 `(ticketSiteCode, ticketNo)`，不依赖车牌、时间或重量模糊匹配。关联信息可以在本地事先保存，也可以在云端由授权库管选择；具体自动/人工入口待确认，不能把某种入口写成已确定要求。

## 3. 人员端 API 清单（建议）

路径相对 `/api/v1`；均为拟新增接口。

| 方法与路径 | 作用 | 岗位 |
| --- | --- | --- |
| `POST /grain-intake/trips` | 登记流转单并分配本趟编号 | 库管 |
| `GET /grain-intake/trips` | 查询工作列表，按阶段、车牌等筛选 | 按岗位授权 |
| `GET /grain-intake/trips/{tripNo}` | 查询事实、版本、关联磅单及阻断原因 | 按岗位裁剪字段 |
| `POST /grain-intake/trips/{tripNo}/supplier-confirmations` | 补选或更正供应商，留存核实及原因 | 授权采购/化验员等 |
| `POST /grain-intake/trips/{tripNo}/inspections` | 新增检测或复检 | 化验员 |
| `POST /grain-intake/trips/{tripNo}/inspection-confirmations` | 确认有效检测及接收/拒收结论 | 化验员 |
| `POST /grain-intake/trips/{tripNo}/unloading-confirmations` | 确认实际粮仓和卸粮完成 | 库管 |
| `POST /grain-intake/trips/{tripNo}/ticket-links` | 关联云端已保存的有效磅单 | 授权库管；自动调用方案另定 |
| `POST /grain-intake/trips/{tripNo}/exit-permits` | 开具正常出门证 | 库管 |
| `POST /grain-intake/trips/{tripNo}/exit-permit-approvals` | 审批正常出门证 | 库管 |
| `GET /grain-intake/trips/{tripNo}/exit-basis` | 查询当前有效正常证或拒收依据及版本 | 门卫 |
| `POST /grain-intake/trips/{tripNo}/exit-confirmations` | 按核验依据版本确认实际出厂 | 门卫 |

供应商及粮仓 CRUD 后续定稿；不提供通用修改状态接口。拒收出厂不要求正常出门证或完整磅单。

## 4. 关联命令（建议）

```json
{
  "siteCode": "F001",
  "operationId": "<调用端保存的原操作标识>",
  "expectedVersion": 7,
  "ticketSiteCode": "F001",
  "ticketNo": "<云端已接收的正式单号>"
}
```

`tripNo` 取路径参数，示例版本仅为格式说明。云端成功返回本趟编号、新版本及关联单号，仍使用 `{code,message,data}`。

1. 验证调用权限、本趟厂区及当前版本，不能通过传入厂区改变归属。
2. 查询已持久化正式磅单，确认有效、入厂收粮方向，厂区、车牌、供应商及粮种与本趟一致。
3. 核对首磅前有效化验、实际粮仓及卸粮事实、两次重量、扣减依据和结果；时间使用实际发生时间，不使用云端接收时间。离线业务依据的具体字段需双端定稿；现有磅单字段不足时不能假装已验证化验版本。
4. 保证本趟只关联一份当前有效磅单，且磅单只关联一趟。在事务中保存关联、审计及幂等结果；相同关联重复请求不重复累计。
5. 前置资料未齐或有冲突时保留已同步磅单及待关联事项，返回明确原因。不覆盖化验、不重新出单、不自动改挂其他同车流转单。

正常开证检查实际粮仓已记录、卸粮已确认、两次过磅完成且已关联磅单有效。关联成功仅代表校验通过，不代表出门证已经审批或车辆已经出厂。

## 5. 幂等、并发和重试

- 新增业务接口沿用统一响应、业务码检查和分页 `records`；前端在 API 层转换。
- 写命令使用持久化 `operationId` 和 `expectedVersion`。该标识仅用于协同命令，与磅单摘要不同；相同标识同内容返回原结果，不同内容拒绝。
- 幂等范围为厂区、本趟、动作及操作标识，登记前按厂区、动作及标识去重。幂等结果与业务同事务提交，先查原结果再判版本，避免成功重试被旧版本误拒绝；一期不自动清理幂等记录。
- 版本冲突须读取最新事实，不自动更换版本重放旧业务意图。结果未知先读当前关联或原操作结果，再重试原命令。
- 网络恢复先同步正式磅单，后关联。同步成功、关联失败只重试关联；两步间不要求分布式事务，本地正式单据不能因此丢失或重复产生。
- 数据库约束每趟唯一出厂记录和磅单唯一关联。重复手机提交、自动和人工同时关联不能生成重复记录。
- 重量沿用十进制吨字符串、最多三位小数，计算使用整数千分吨；检测值、比例及舍入按正式客户标准定稿。

| 情况 | 建议 HTTP / 原因 | 行为 |
| --- | --- | --- |
| 参数或计算不一致 | 400 / `invalid_input`、`calculation_mismatch` | 展示原因，不自动改数 |
| 未登录/无权限 | 401 / 403 | 登录或处理授权 |
| 本趟或磅单不存在 | 404 / `trip_not_found`；409 / `ticket_pending` | 核对编号，或等待原磅单同步 |
| 版本变化或前置未齐 | 409 / `version_conflict`、`prerequisite_pending` | 刷新事实，补齐前序 |
| 重复关联冲突 | 409 / `ticket_link_conflict`、`operation_conflict` | 暂停核查，不覆盖 |
| 磅单失效或流转单阻断 | 409 / `ticket_invalid`、`trip_blocked` | 禁止开证放行 |
| 临时不可用 | 503 / `temporary_unavailable` | 保留原参数退避重试 |

稳定错误原因字段与公共错误层的兼容性在实现时核对，不直接改动既有错误包。

## 6. 身份与有效性边界

人员端复用员工账号及后端岗位授权，不信任请求体自报姓名。现有厂端同步无来源认证，厂区编码不是凭据；如果后续选择厂端自动关联，调用身份及授权方案需另定，不擅自要求新增厂端凭据。人工关联先使用已登录库管权限。

云端只能掌握已同步事实：离线首磅后可能有人重新确认化验，联网后须核对时间和依据冲突，不宣称云端可以实时禁止离线称重。审批后及出厂后联动更正仍不在一期。

开证、审批和正常放行均检查当前已知磅单有效性；接收作废与关联流转单阻断在同一云端事务生效。但厂端已作废而尚未上传时，云端可能仍显示有效。审批至出厂期间怎样保证有效性仍需明确，不能用事后关联替代这个问题；不得未经确认新增在线称重门槛。

在途改码、已关联磅单作废/重开和跨端纠错另行细化，不自动改写历史编码或已出厂事实。

## 7. 已实现的流转单查询与关联接口

2026-11-11 已实现厂端只读查询和磅单关联，路径相对 `/api/v1`：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /weighbridge/sync/trips?siteCode=&plate=` | 按车牌查询候选流转单、生效化验和建议扣减项 |
| `GET /weighbridge/sync/trips/{tripNo}?siteCode=` | 查询单张流转单详情 |
| `POST /weighbridge/sync/trips/{tripNo}/link` | 磅单同步确认后按流转单号关联正式磅单 |

接口沿用厂区编码校验，不新增厂端凭据；厂区编码不存在或停用返回 401。候选包含 `linkable` 和 `blockers`，多张候选由厂端人工选择，不自动认定。关联接口幂等，相同流转单和磅单重复调用返回成功；已关联其他磅单或流转单、前置卸粮未完成、时间顺序不一致时返回 409，厂端保留待关联状态并重试。

扣减规则由新增的 `grain_deduction_rule` 和 `grain_deduction_rule_range` 配置，`grain_deduction_category` 维护扣减类别字典。云端只下发比例或固定吨数，厂端在回磅时按最终净重折算。管理接口为 `/grain-intake/deduction-categories` 和 `/grain-intake/deduction-rules`，需要 `grain-intake:deduction-rules` 权限。

## 8. 契约验证清单

- 断网本地称重、出单、打印成功，联网后依次同步和关联；没有云端准备调用也能完成本地操作。
- 磅单同步成功、关联失败或回执丢失后，原请求重试不重出单、不重复累计。
- 同车多趟严格按编号关联；错厂区、错方向、错供应商/粮种、错化验或重量均不静默通过。
- 离线首磅后有效化验被修改，关联时发现不一致并阻断开证。
- 首磅未上云仍能按现场事实确认卸粮；未记录实际仓及卸粮完成不能正常开证。
- 门卫正常/拒收两条路径各按有效依据确认，重复或并发操作只产生一条出厂记录。
- 已同步作废阻断放行；未上传作废的处理方案另行确认与验证。
- 客户提供正式标准后，双端用同一组水分区间边界和舍入测试向量验证计算。

本清单尚未执行，现有同步测试不能代替新增关联与业务校验测试。

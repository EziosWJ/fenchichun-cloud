# 流转单、化验关联与出门证：当前管理端实现

2026-11-06。本文记录本轮经访谈确认后实现的范围；原粮完整方案的其余规划继续保留。本轮仅现有电脑管理端，不含微信小程序、仓库档案、库存账、自动扣减、取消送货退厂或审批后/出厂后联动更正。

> 目测物料的检验与出厂规则见[物料检验方式与流转约定](material-inspection-method.md)；以下化验步骤适用于检验方式为化验的物料。

## 1. 使用方式

1. 库管在“流转单”登记厂区、车牌和粮种；供应商可待核实，司机及合同编号选填。同车再送粮另建一张流转单。
2. 在流转单化验页新建化验单，自动带入厂区、车牌、粮种、供应商等信息；也可选择已有的独立化验单进行关联。化验单须选择厂区，关联时厂区、车牌、粮种、供应商须一致，一张化验单不能归属多趟；已有复检关系不能跨趟绑定。
3. 化验员确认检测结果后，在流转单下点击“设为本趟生效”。一张流转单可关联多张化验单，但同一时间仅有一张生效。新建复检或确认新的复检结果不会自动替换生效指向；原检测结果保留。已关联单新建复检继承本趟归属。
4. 接收后，库管在现场首磅、卸粮完成时记录实际卸粮地点编号或名称，确认卸粮。本轮只有地点文本，不创建仓库或库存。磅房仍本地称重、打印；联网后先同步正式磅单，再按出单厂区编码和单号关联到流转单。
5. 卸粮已确认、有效磅单已关联后，库管开具出门证，再审批；门卫核验后在实际放行时点击确认出厂。开具、审批和实际出厂分别留存。
6. 化验拒收时，门卫在“出门证 → 拒收退厂”查看生效化验单及拒收说明，直接确认实际出厂，不另开正常出门证、不要求完整磅单。已退厂记录仍可按已出厂筛选查询。

## 2. 校验与保留规则

- 正式确认化验的单位及草稿/作废规则继续沿用[上一阶段](laboratory-phase-one.md)。确认后不覆盖检测字段。
- 更正流转单时，已有已确认化验、卸粮或磅单即不能覆盖车牌、粮种、供应商及厂区；已作废化验不阻止在其他前提满足时更正登记，旧结果保留。草稿若与更正后的登记不一致，需纠正再确认，不自动改写已确认化验。
- 卸粮后或已关联磅单、已开证、已出厂时不再更改化验依据；不能通过化验页作废、编辑或创建复检绕过限制。卸粮前作废生效单会清空生效指向，需重新指定其他已确认单。
- 关联磅单核对其当前厂区归属、入厂方向、车牌、粮种、供应商、有效状态及时间先后。化验确认与生效应在实际首磅之前，现场卸粮确认应在两次称重之间；晚同步保留现场时间，冲突阻断，不自动覆盖。
- 云端不需要先收到首磅回执才能办理现场卸粮确认。首次/二次过磅均不要求先调用云端准备接口，符合本地称重、联网补传方式。
- 同一有效磅单仅能关联一张流转单，同一流转单不能改挂另一张磅单。已关联磅单作废时：尚未开证的流转单自动解除关联、记录系统事件并回到接收待完成，可重新关联重开后的磅单；已开证的流转单显示需核查，阻断审批和正常放行。
- 磅单详情分别展示实际净重（毛重减皮重）与扣减后重量（v3及以上磅单的最终净重）；v2磅单没有扣减后重量，不回退用实际净重冒充。
- 记录版本用于防止并发覆盖。重复确认出厂核对相同历史依据后返回原结果，不重写出厂时间和人员；使用不同依据则拒绝。
- 流转过程记录与通用操作审计在业务事务中提交。化验更正、复检、指定位于同一流转单的生效单、开证、审批和出厂均可回看。

## 3. 菜单与授权

新增流转单与出门证菜单，初始授权ADMIN，其他岗位通过既有角色菜单管理分配：

| 操作 | 服务端要求 |
| --- | --- |
| 登记、更正、关联化验、卸粮、关联磅单、开具出门证 | 流转单菜单权限 |
| 创建/确认/复检化验、指定本趟生效化验单 | 化验单菜单权限；从流转单详情办理时同时需要该页访问权限 |
| 审批出门证 | 出门证及流转单菜单权限，供库管使用 |
| 查看核验依据、正常/拒收确认出厂 | 出门证菜单权限，门卫无需流转单管理权限 |

菜单显隐不替代服务端校验。流转单与出门证详情URL同样受其父菜单权限保护。

## 4. API 与代码入口

- `/api/v1/grain-intake/trips`：流转单列表、登记；`/{id}` 查询/更正。
- `/api/v1/grain-intake/trips/{id}/{action}`：明确业务命令，包含关联化验、指定生效、卸粮、关联磅单、开证、审批、确认出厂。不提供任意更新状态接口。
- `/api/v1/grain-intake/trips/{id}/ticket-candidates`：查询本趟可关联的正式磅单及不可关联原因。
- `/api/v1/grain-intake/permits`：正常出门证列表。
- `/api/v1/grain-intake/rejections`：拒收退厂及历史查询。
- `/api/v1/grain-intake/exit-basis/{id}`：门卫按流转单核验依据。
- 化验单既有API增加可选`tripId`、`siteCode`及列表归属筛选，保留独立建单能力。确认化验前须补齐厂区；历史已关联化验单在迁移时按流转单厂区回填。完整字段以生成的Swagger为准。

后端位于`server/internal/grainintake/`，化验关联约束位于既有`server/internal/laboratory/`；前端位于`web/src/pages/grain-intake/`。没有改变现有磅单同步载荷或摘要规则，也没有替厂端开发新的称重逻辑。

## 5. 验证与使用限制

开发库schema和菜单迁移已执行。新增数据库契约测试覆盖多化验唯一生效、复检继承归属、跨趟拒绝、正常开证审批与出厂分离、重复出厂、拒收退厂、磅单作废阻断，以及真实HTTP接口和门卫权限。Docker集成测试使用隔离库；本地环境可用开发库的外层事务回滚方式执行相同核心契约，测试数据不作为业务数据保留。

本轮未增加磅房离线取得化验依据的机制；仍需现场联调明确传达方式。云端只能核验已经同步的磅单状态：厂端已作废但尚未上传时仍有同步滞后，不能宣称实时放行保证已解决。审批后联动更正和在途改码处理继续暂缓，不提供强制放行绕过按钮。

# 汾池春小程序 UI 设计系统与开发规范

> 状态：Phase 0 已冻结（规范基线）
> 适用范围：`fenchichun-cloud/miniprogram`
> 说明：本文是工程落地契约；页面实现以本文的 Tokens、页面范式与验收约束为准。需要调整规范时，先更新本文再改代码。

## 1. 文档地位与优先级

开发 UI 前按以下顺序判断：

1. 业务契约、`AGENTS.md`、`CONTEXT.md`：不得为了视觉删改业务字段、状态、校验和权限。
2. 本文与 `src/app.css` 中的 Design Tokens：颜色、字号、间距、圆角、组件范式。
3. 现有页面的结构模式与 TDesign 组件能力。
4. TDesign 默认视觉。

出现以下情况必须先停下来确认，不要自行发挥：

- 需要新增业务状态、统计数字、列表字段或页面入口。
- 需要新增第二套 UI 组件库、图标库或 Web 字体。
- 需要改变导航模式、tabBar 数量或页面信息架构。
- 设计样稿与现有业务语义冲突（例如样稿有 3 个 tab，而当前业务只有 2 个）。

品牌文案统一使用「汾池春」。历史样稿中的「沣池春」不进入代码。

## 2. 设计方向

关键词：**工业温润极简（Industrial Premium）+ 作业清晰（Operational Clarity）**。

- 浅暖白底、深石墨文字、砖红强调色、极轻量粮仓装饰。
- 以留白、对齐、字重和细分隔线建立层级，不靠重阴影和满屏卡片。
- 一屏只保留一个主要行动；数据密集区保持安静。
- 工作台先给“当前要做什么”，详情页先给“车辆是谁、依据是什么、确认后会发生什么”。
- 保持单据/回执的秩序感：左侧标签、右侧值、细线分隔、紧凑行高。

### 2.1 视觉基准识别结论

- **双工作台**：库管为角色横幅 + 搜索/筛选 + 「待处理车辆」分组 + 单组列表；每行只有车牌、粮种·供应商、一个动作按钮；动作红/橙区分主次，但无状态点、时间、编号等多余字段。门卫为搜索 + 三段时间 Tab（待放行/已放行/异常或拒收）+ 单组「待放行车辆」；行按钮统一「核验放行」，不直接放行。两屏都没有顶部统计数字，底部为原生风格 tabBar。
- **双详情页**：标题竖线 + 车牌区 + 两块摘要 + 「当前步骤/时间线」分段控件 + 单据内容 + 吸底主按钮。门卫时间线用品牌色圆点/勾、时间与「详情 ›」入口，当前节点为空心圆，底部为「确认放行」。详情页的信息顺序与“放行必须在详情完成”的约束由此确定。样稿的浅底车牌大卡保留“外框 + 淡背景”的方向，落地为全宽车牌面板，并去掉重复的状态与业务摘要。
- **图标与插画**：线性图标统一砖红描边、圆角端点；粮仓插画为低对比暖色装饰，不承载业务信息。图标优先使用 TDesign 已有语义图标，定制图标只用于品牌头部、tabBar 等明确需要差异化的位置。

### 2.2 不可妥协的八条

1. 工作台不出现任何顶部统计数字或「最近完成」。
2. 车辆列表每行只有 2 层信息 + 1 个动作；完整字段进详情。
3. 一个视图只有一个主要 CTA；品牌红不大面积铺底。
4. 门卫列表只负责进入核验详情，最终放行必须在详情页二次确认。
5. 页面背景浅暖白，文字深石墨，品牌砖红只做强调。
6. 正文不小于 24rpx；车牌/单号/供应商不截断。
7. 触控目标不小于 88rpx；吸底栏必须含安全区。
8. 设计截图只对照，不贴图；页面全部原生组件实现。

## 3. Design Tokens

### 3.1 颜色

以下色值为本项目 Design Tokens。标记“派生”的是为满足小程序对比度和控件状态补充的值；所有色值需在真机验收后微调。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--fc-brand` | `#A74532` | 主按钮、当前 Tab、选中态、关键强调 |
| `--fc-brand-pressed` | `#943B2B` | 品牌色按下态 |
| `--fc-brand-soft` | `#F7EEE7` | 品牌浅底、状态浅底、旗帜性区块 |
| `--fc-accent` | `#DE8B25` | 次级动作橙，谨慎使用 |
| `--fc-accent-pressed` | `#C4771B` | 派生，橙按钮按下态 |
| `--fc-accent-soft` | `#FBF1E3` | 派生，待处理状态浅底 |
| `--fc-text` | `#25282B` | 标题、正文、车牌 |
| `--fc-text-secondary` | `#777674` | 说明、标签、次要信息 |
| `--fc-text-placeholder` | `#A5A39F` | 输入占位符 |
| `--fc-text-disabled` | `#C9C5BF` | 派生，禁用文字 |
| `--fc-bg` | `#F7F6F3` | 页面背景 |
| `--fc-surface` | `#FFFFFF` | 卡片、列表容器、输入面 |
| `--fc-surface-muted` | `#FAF8F5` | 派生，单据内浅底、次级面 |
| `--fc-control-track` | `#F1EDE7` | 派生，分段控件轨道、筛选项底 |
| `--fc-border` | `#E8E3DD` | 分隔线、卡片边框、输入框边框 |
| `--fc-border-strong` | `#D9D3CB` | 派生，需要更明确边界时使用 |
| `--fc-success` | `#27865B` | 成功、已完成、接收 |
| `--fc-success-soft` | `#E8F3ED` | 派生，成功浅底 |
| `--fc-warning` | `#DE8B25` | 待处理、警示动作 |
| `--fc-warning-text` | `#8A5A12` | 派生，浅底上的警示文字，保证对比度 |
| `--fc-warning-soft` | `#FBF1E3` | 派生，警示浅底 |
| `--fc-error` | `#B33F35` | 错误、拒收、危险操作 |
| `--fc-error-soft` | `#FBEDEB` | 派生，错误浅底 |

颜色规则：

- 品牌色是强调色，不是页面底色。不要把所有标题、所有按钮都染成品牌色。
- 大面积不得铺品牌红；整屏红色底、红色渐变按钮、红色营销 Banner 均禁止。
- 页面背景用 `--fc-bg`，内容面用 `--fc-surface`；不要用纯白整页再叠灰卡片，也不要用冷灰 `#f5f6f8`。
- 状态不能只靠颜色。必须同时有文字，必要时再加图标或位置信号。
- 橙色只用于“待处理/交接类动作”（如开出门证、去目测）和待处理提示，不用于普通主按钮。
- 绿色只表达成功/接收/已完成；红色只表达错误/拒收/危险操作。
- 页面内不允许再出现新的十六进制色值；确需新增时先补进本节和 token 层。
- 本轮不实现 DarkMode，`theme.json` 维持空配置；后续若要做，单独评估对比度、TDesign 暗色变量和图片资源，不在页面里零散加暗色样式。

### 3.2 字体与字号

系统字体优先，不加载 Web 字体。375px 设计基准下 `1px = 2rpx`。

| 角色 | px | rpx | 字重 | 行高 | 用途 |
| --- | --- | --- | --- | --- | --- |
| 页面主标题 | 22 | 44 | 600 | 1.3 | 工作台、台账、详情页标题 |
| 详情车牌主标题 | 28–32 | 56–64 | 650 | 1.15 | 仅详情页车辆主卡 |
| 列表车牌 | 20 | 40 | 600 | 1.25 | 工作台/台账列表首行 |
| 区块标题 | 17 | 34 | 600 | 1.3 | 「待处理车辆」「核验依据」 |
| 正文 | 15–16 | 30–32 | 400 | 1.5 | 说明、字段值、表单输入 |
| 次要正文 | 13–14 | 26–28 | 400 | 1.45 | 第二行、辅助说明、时间 |
| 按钮文字 | 15 | 30 | 600 | 1 | 主要/次级按钮 |
| 标签/微文案 | 12 | 24 | 500 | 1.3 | 状态标签、极小说明，正文下限 |

规则：

- 正文最小 `24rpx`（12px）。禁止用 10–11px 或 20–22rpx 把信息塞进列表。
- 中文不截断车牌、单号、供应商；长文本允许换行，使用 `overflow-wrap: anywhere`。
- 车牌是视觉锚点，使用深石墨色粗体，不使用蓝色车牌贴片，不使用等宽字体冒充车牌。
- 数字可使用 `font-variant-numeric: tabular-nums`，但不要混用多套字体。
- TDesign 默认 `28rpx` 正文偏小；业务正文使用 `30rpx`，单据行使用 `28–30rpx`，caption 最低 `24rpx`。

### 3.3 间距

基线：4 / 8 / 12 / 16 / 20 / 24 px，对应 8 / 16 / 24 / 32 / 40 / 48rpx。

| 场景 | 值 |
| --- | --- |
| 页面左右安全边距 | `32rpx`（16px） |
| 页面顶部内容间距 | `24–32rpx` |
| 区块之间 | `32rpx` |
| 卡片内边距 | `32rpx` |
| 列表行上下内边距 | `24–28rpx` |
| 列表行最小高度 | `160–176rpx`（80–88px） |
| 标签与值之间 | `16–24rpx` |
| 按钮组之间 | `16rpx` |
| 表单字段之间 | `24–32rpx` |

### 3.4 圆角

| Token | 值 | 用途 |
| --- | --- | --- |
| 小圆角 | `16rpx`（8px） | 输入框、小标签、缩略图 |
| 中圆角 | `24rpx`（12px） | 搜索框、按钮、分段控件、行内动作 |
| 大圆角 | `32rpx`（16px） | 卡片、分组列表容器、横幅 |
| 胶囊 | `999rpx` | 仅状态标签、筛选 chip、头像 |

不要使用 40rpx 以上的超大圆角做“软萌卡片”；同一层级只用一个圆角。

### 3.5 尺寸、触控与安全区

| 项 | 要求 |
| --- | --- |
| 主按钮高度 | `88rpx`（44px） |
| 搜索框高度 | `88rpx` |
| 输入框高度 | `88rpx`；登录页适老化用 `104rpx` |
| 列表行最小高度 | `160rpx`，建议 `168rpx` |
| 图标尺寸 | `32–40rpx`，列表动作箭头 `28–32rpx` |
| 触控目标 | 不小于 `88rpx × 88rpx`；小图标必须有扩展热区 |
| 吸底操作栏 | `24rpx` 上内边距 + `88rpx` 按钮 + `24rpx` 下内边距 + `env(safe-area-inset-bottom)` |
| 底部导航 | 使用原生 tabBar；页面内容底部预留 tabBar 与安全区 |
| 顶部横幅 | 内容区 `144–180rpx`，默认 `160rpx`（80px） |
| 大屏约束 | 根容器 `max-width: 750px`，居中，避免 iPad/PC 拉伸 |

安全区写法保持 `constant()` 在前、`env()` 在后；禁止硬编码 34px、44px、88px 等状态栏/导航栏魔法数。默认使用系统导航栏；当前仅登录页使用 `navigationStyle: custom` 的沉浸式照片头部，状态栏高度由 `wx.getWindowInfo().statusBarHeight` 提供，不写死。

### 3.6 边框、阴影与层级

- 优先 1rpx 边框和留白，不用阴影制造层级。
- 卡片默认无阴影，或仅使用极轻阴影；禁止厚重弥散阴影。
- 分组列表用一个整体容器 + 行间 1rpx 分隔线，不为每行做悬浮卡。
- 浮层/弹窗使用系统或 TDesign 默认层级，不引入玻璃拟态、磨砂背景、渐变蒙层。

## 4. TDesign 映射

只覆盖语义变量，不整体重写 TDesign 内部 DOM。建议在 `app.css` 的 `page` 选择器中维护：

```css
page {
  --td-brand-color: #A74532;
  --td-brand-color-active: #943B2B;
  --td-brand-color-light: #F7EEE7;
  --td-text-color-primary: #25282B;
  --td-text-color-secondary: #777674;
  --td-text-color-placeholder: #A5A39F;
  --td-text-color-disabled: #C9C5BF;
  --td-bg-color-page: #F7F6F3;
  --td-bg-color-container: #FFFFFF;
  --td-bg-color-secondarycontainer: #FAF8F5;
  --td-border-level-1-color: #E8E3DD;
  --td-component-stroke: #E8E3DD;
  --td-component-border: #E8E3DD;
  --td-success-color: #27865B;
  --td-warning-color: #DE8B25;
  --td-error-color: #B33F35;
}
```

规则：

- 主操作 `<t-button theme="primary">`；次级操作 `variant="outline"` 或默认主题；危险操作才用 `danger`。
- 一个视图只保留一个主要 CTA。吸底确认用 `block size="large"`；列表内联动作用 `size="small"`，但视觉高度仍按 80–88rpx 控制。
- `t-tag` 统一由 `status-tag` 封装，使用 `variant="light"`；语义色只用 `success` / `warning` / `danger` / `primary`。
- `t-empty`、`t-loading` 通过 `empty-state` / `loading-state` 使用，保持文案和间距统一。
- 搜索框当前是原生 `input` + `.search-input`，不要无理由换成 `t-input`。
- 图标优先 TDesign 已有语义图标；定制图标仅用于品牌头部、tabBar 等明确需要差异化的位置，不形成第二套页面图标体系。
- TDesign 组件由 `TDesignResolver` 自动注入，页面 JSON 不手写 `t-*` 的 `usingComponents`。
- 保持 `app.json` 的 `"style": "v2"` 与 `"componentFramework": "glass-easel"`。

## 5. 素材与图像规范

除工作台横幅背景 `public/ui-kit/silo-raster-reference.png` 外，设计截图与其他新增运行素材不纳入本仓库；本文只固化规格与使用约束，避免把设计截图当页面内容。需要引入自定义图标、插画或横幅时，先确认 TDesign 或现有能力无法满足，再按本节执行。

### 5.1 规格

| 素材 | 设计尺寸 | 交付格式 | 用途 |
| --- | --- | --- | --- |
| 工作台横幅底图 | `750×160rpx`（@2x `1500×320`） | PNG/JPG | 工作台顶部横幅 |
| 粮仓插画 | `330×140rpx`（@2x `660×280`） | 透明 PNG | 横幅右侧装饰 |
| 线性图标 | `48×48rpx`（@3x `72×72`） | 透明 PNG | 品牌头部、tabBar 等 |
| tabBar 图标 | `48×48rpx`（@3x `72×72`） | PNG | `app.json` 引用 |

- 图标统一线宽、圆角端点和砖红描边，不要混入第二套线宽。
- 插画低对比、暖米色，不承载文字和业务信息。
- 横幅底图不包含文字，标题和说明由原生组件叠加。

### 5.2 技术约束

- 小程序 WXSS 不要用本地路径的 `background-image`。横幅和插画用 `<image>` 绝对定位叠放。
- 优先 PNG；SVG 只作为源文件，确认目标基础库稳定支持后再统一替换，不能只在一页使用。
- 装饰图必须 `aria-hidden="true"`；有意义的图标按钮必须有 `aria-label`。
- 不把 SVG 当模板拼接动态文本；所有业务文字用原生 `<text>` / `<view>`。
- 不使用远程装饰图、外链字体、CSS 动画库。
- 未引入插画素材时，可用低对比 CSS 几何装饰模拟粮仓轮廓；不得引入远程图片或设计截图。
- 压缩 PNG；除极小图标外不使用 base64。

### 5.3 使用位置

- 工作台横幅底图：高 `160rpx`，宽 `100%`，`mode="aspectFill"`，放在内容底层。
- 粮仓插画：宽 `330rpx`，高 `140rpx`，底部对齐，透明度可降至 0.8–0.9；不得遮挡标题和搜索。
- 角色图标：工作台横幅左侧，尺寸 `40rpx` 左右，颜色与品牌一致。
- tabBar 图标：沿用现有 `public/tabbar/`，由 `app.json` 引用；选中态砖红，未选中态次要灰。
- 行内图标：优先 TDesign；搜索、筛选、箭头、勾选等语义图标不要混用多套风格。

## 6. 页面范式

### 6.1 通用骨架

```xml
<view class="screen">
  <loading-state wx:if="{{loading}}" text="正在加载" />
  <error-state wx:elif="{{error}}" text="{{error}}" bind:retry="load" />
  <empty-state wx:elif="{{!items.length}}" text="暂无数据" />
  <block wx:else>
    <!-- 内容 -->
  </block>
</view>
```

- 页面左右边距 `32rpx`，底部预留安全区；有 tabBar 的页面还要预留 tabBar 高度。
- 加载、空、错误三态必须覆盖；错误态必须可重试。
- 首屏优先展示当前任务，不展示统计面板、最近完成、管理后台式仪表盘。

### 6.2 工作台（库管 / 门卫）

结构固定为：

1. 顶部角色横幅：可全宽贴边，使用低对比粮仓背景；角色图标直接放在背景上，不加白色容器，也不放左侧品牌竖线；只显示角色名，不显示副标题。右侧粮仓装饰不遮挡文字。
2. 搜索（库管可加筛选）：搜索车牌 / 供应商 / 出门证号。库管「登记」为搜索行右侧常驻主操作，与搜索栏一起吸顶，不单独占整行；筛选是可选能力，没有真实筛选需求时不为了像样稿而加无效按钮。
3. 分组标题：左侧品牌竖线 + 如「待处理车辆」「待放行车辆」；**不显示数量**。完整台账从底部「台账」tab 进入，不在标题右侧放「查看全部」。
4. 单组任务列表：每行只允许“车牌 + 粮种·供应商 + 一个动作按钮”。小屏优先减少页面边距和行内边距，让列表尽量撑满。
5. 底部原生 tabBar：工作台 / 台账 / 我的 三个 tab；台账页承载全部流转单查询。

禁止：

- 顶部数字统计卡（待卸货 16 / 待开证 9 / 待目测 5）。
- 「最近完成」模块。
- 列表行叠加当前节点、状态点、重复标签、时间、编号。
- 每行一个悬浮卡片或重阴影。

库管动作示例：

| 动作 | 颜色 | 说明 |
| --- | --- | --- |
| 登记磅单 | 品牌红 | 当前主任务 |
| 开出门证 | 次级橙 | 交接类动作 |
| 去目测 | 次级橙 | 交接类动作 |

门卫：

- Tab 使用「待放行」「已放行」，不附加数量。当前业务只有这两个筛选口径；「异常/拒收」需产品确认筛选规则后再加，未确认前不得把拒收车辆从待放行中隐藏。
- 行按钮统一「核验放行 →」，点击进入核验详情。
- 列表页不得直接确认放行。

横幅建议高度 `176rpx`；标题 `44rpx/600`；角色图标 `56rpx`；只显示角色名，不显示副标题；左侧不放竖线；右侧背景图不遮挡文字，文字区最大宽度约 62%。

### 6.3 列表 / 台账

- 搜索在前，筛选 chip 可横向滚动，选中态用品牌色文字/浅底/边框，不用整块品牌红。
- 分组容器：白底、`32rpx` 圆角、`1rpx` 边框；行间 `1rpx` 分隔线。
- 行内信息不超过 2 层 + 1 个动作入口；完整台账字段进入详情。
- 行高 `160–176rpx`，动作按钮高度 `80–88rpx`，触控不小于 `88rpx`。
- 车牌 `40rpx/600`；第二行 `26rpx` 次要色；箭头 `28–32rpx`。
- 空结果给出下一步：清空搜索、切换筛选、去登记。

### 6.4 详情 / 作业页

采用：

1. 页面标题（库管、门卫详情使用原生导航标题；门卫待放行显示「核验放行」，已放行显示「放行记录」）+ 全宽车牌面板：淡暖底 + 暖灰边框，车牌居中，省份与号码同字号、同字重（约 `56rpx`）。
2. 两块关键摘要：门卫正常出厂为「出门证状态 / 审批时间 + 供应商 / 粮种」，拒收退厂为「放行依据 / 检验结果 + 供应商 / 粮种」；出门证号下沉到核验依据，净重等库管/磅房数据不进入门卫顶部摘要。
3. 「当前步骤 / 时间线」分段控件。
4. 主内容区：当前步骤放可填写字段与一个主要操作；时间线放业务节点、时间、必要的「详情」入口。
5. 吸底主操作。

规则：

- 全宽车牌面板不在下方重复状态、厂区、粮种、供应商；状态由吸底按钮和时间线当前节点表达，业务摘要由两块摘要卡和记录区承担。
- 当前任务不单独重复展示，状态由吸底按钮、交接提示和时间线当前节点表达。门卫待放行不显示当前任务卡；已放行只显示「已实际出厂」和出厂时间。
- 已出厂 / 已放行记录进入只读模式：不显示当前步骤/时间线 Tab、出门证状态、当前任务和吸底按钮；只保留完成状态与时间、放行依据摘要、单据记录和流转时间线。
- 摘要卡最多两块，不要堆 3–4 个指标卡。
- 用「当前步骤 / 时间线」替代 6 段进度条；历史节点不得与当前操作混在一起。
- 时间线当前节点置顶，历史事件按「新 → 旧」排列；最后一个历史节点不再向下连线。
- 关键字段（净重、扣减后重量、审批状态）只强调 1–2 处。
- 门卫放行必须在详情页完成二次核对；提交前有明确确认，确认文案包含车牌、厂区、依据。
- 吸底按钮不遮挡最后一行；页面底部预留 `200rpx + safe-area`。

### 6.5 表单 / 登记

- 字段按业务分组；label `26–28rpx/600`；输入控件高 `88rpx`；字段间距 `24–32rpx`。
- 必填项用红色星号 + 字段级错误，不用 toast 代替校验。
- 车牌行：省份选择 `160rpx` + 号码输入自适应 + 拍照按钮 `88rpx` 见方；拍照按钮有 `aria-label`。
- 可选信息默认折叠，展开/收起文案明确。
- 提交按钮放表单末尾或吸底；提交中 loading + disabled，防重复提交。
- 禁用/不可提交时说明原因，不只把按钮变灰。

### 6.6 登录 / 我的

登录（沉浸式照片头部，用户确认的例外范式）：

- 结构固定为：全幅酒厂实景照片 → 暖棕黑渐变遮罩 → 象牙白品牌标记 → 暖白圆角抽屉 → 白色登录卡。
- 头部照片层高度约 `68vh`，实际可见的照片与品牌区固定为 `42vh`，其余部分由暖白抽屉覆盖；抽屉以 `48rpx` 圆角压住照片下缘，避免图片出现硬边。
- 照片上叠暖棕黑渐变（顶部约 `78%` → 中部 `26%` → 底部透明），保证状态栏、白色品牌字和粮穗标记可读。
- 品牌标记用象牙白线性粮穗 + 象牙白宋体「汾池春」+ 细分隔线；不用红色印章、浅色圆底或额外的米色品牌卡。
- 暖白抽屉内放白色登录卡；砖红只出现在输入图标、显示密码和登录按钮上。
- 登录页使用 `navigationStyle: custom`，不在照片上重复系统导航标题；顶部内边距由 `wx.getWindowInfo().statusBarHeight` 计算。
- 照片必须为酒厂自有或已授权素材，替换说明见 [登录页背景图](login-hero.md)；不得把粮仓线稿放大当背景。
- 输入框 `104rpx`，主按钮通栏 `104rpx`（适老化）；错误信息靠近表单，不用一闪而过的 toast 代替。
- 键盘弹出时照片与品牌保持不动，登录抽屉以 `260ms` 缓动上滑盖住品牌，顶部保留状态栏与胶囊所在的深色照片条；输入框和 placeholder 随布局同步移动，不使用整页 `transform`。
- 抽屉展开由 `focus`/`blur` 控制，失焦后延迟 `200ms` 再收起；切换账号/密码时新焦点会取消收起，避免页面回落再升起。输入框保持 `adjust-position="{{false}}"`，不让系统再次滚动照片。键盘真正收起后抽屉回落。
- 文案只保留字段 placeholder 与必要提示，其余区域保持安静、克制。

我的：

- 身份卡：头像/姓名/岗位；信息用 label/value 行。
- 不做统计卡片、不做花哨图表。
- 退出登录是次要操作，用 outline 危险色，不用品牌实底。

### 6.7 状态页与反馈

- 加载：`t-loading` + 文案；同页最多 1 个；已有内容时不要全屏遮挡。
- 空：轻量图标 + 标题 + 说明 + 可选下一步动作；不要只显示「暂无数据」。
- 错误：说明发生了什么 + 重试按钮；保留用户已输入内容。
- 成功：toast 后刷新/移除对应行；关键业务不能只靠 toast 作为唯一反馈。
- 确认：简单场景用 `wx.showModal`；复杂/关键场景可用页面内确认区或底部弹层，但不得引入第二套 UI 库。确认文案必须具体说明对象和后果。

## 7. 交互与文案

- 搜索支持输入、清除、空结果提示；输入过滤建议 200–300ms 防抖，避免每敲一个字都请求。
- 任务点击进入详情；处理后列表状态更新或移除；返回工作台时刷新。
- 请求中按钮 loading 且防重复提交。
- 无权限时明确提示，不显示空白页。
- 错误可重试；网络错误与业务错误文案区分。
- 固定操作栏、键盘弹起、长文本、大数字都要验证。
- 文案短、动词开头、说人话；按钮文案说清楚点击后会发生什么。
- 不使用感叹号堆情绪，不使用「智能」「一键」等夸张词。

## 8. 禁止事项

- 不恢复顶部指标统计面板或「最近完成」列表。
- 不把大段业务细节堆回车辆列表；避免过度信息密度和小字。
- 不用一张静态图代替可操作页面；不模仿设计样稿中的 iPhone 外框和透视效果。
- 不使用花哨渐变、重阴影、巨大圆角、强烈磨砂玻璃、营销 Banner。
- 不把门卫「核验放行」列表按钮理解为直接确认放行。
- 不使用蓝色车牌贴片；车牌用深石墨文字。
- 不使用紫色/蓝色渐变、霓虹色、玻璃拟态。
- 不使用 emoji 当图标；不引入第二套图标库。
- 不使用低于 `24rpx` 的正文；不用浅灰字叠浅灰底。
- 不在吸底栏省略安全区；不用 fixed 覆盖 tabBar 或胶囊。
- 不使用本地 `background-image` 引 Banner/插画。
- 不为了视觉完整删掉业务字段、状态、校验或错误提示。

- [ ] 首屏没有统计卡、最近完成、营销 Banner。

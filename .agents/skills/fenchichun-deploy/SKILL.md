# 汾池春部署

默认目标为 `ubuntu@82.157.101.92`、`/opt/fenchichun` 和 systemd 服务 `fenchichun`；用户指定其他目标时以用户要求为准。SSH 遇到密钥交换超时可尝试 `-o KexAlgorithms=curve25519-sha256`，并校验服务器主机密钥。

## 更新部署

1. 检查目标服务、配置和当前工作区；执行 `task build`，确认构建成功且产物架构与服务器匹配。`base-go-api` 已内嵌前端；`base-go-migrate` 用于数据库迁移。
2. 将 `bin/base-go-api`、`bin/base-go-migrate` 和 `server/migrations/` 上传到临时位置并校验完整性。保留服务器现有生产配置、上传文件和账号密码记录；保留上一版可执行文件以便程序回退。
3. 在部署目录使用 `APP_ENV=prod` 和新迁移程序执行 `up --kind all`。迁移失败时停止部署并报告，不启动新程序。迁移可能不可逆，程序回退不代表数据库回退。
4. 替换程序和迁移文件，重启 `fenchichun` 服务。
5. 检查 systemd 状态、`/health`、`/ready` 和首页；确认外网访问情况并报告地址、结果及未完成事项。失败时查看日志，结合数据库迁移状态判断是否恢复上一版程序。

## 首次部署

确认目标架构和目录、数据库及账号未被占用；按需创建专用数据库账号、生产配置、上传目录和 systemd 服务，然后执行上述构建、迁移、启动及验证步骤。生成独立 JWT 密钥并替换默认管理员密码。不要覆盖既有数据库、账号或配置。

生产配置及密码留在服务器，限制文件权限；不将密码写入 skill、源码或命令输出。现有服务器的生产配置为 `/opt/fenchichun/configs/config.prod.yaml`，账号记录为 `/opt/fenchichun/账号密码.md`。更新部署不重置账号或密码。

当前服务使用 HTTP；如用户要求 HTTPS，先确认域名、证书及服务器现有代理配置，再按实际环境配置。
